## Adversarial Issues

1. **Major** — [eval/metrics.py:236](../../../eval/metrics.py#L236), [eval/run_eval.py:461](../../../eval/run_eval.py)
   `min_overlap_voxels` is not validated. If set to `0`, every GT/pred component with max overlap `0` is counted as detected/TP when both masks are nonempty.
   **Fix:** reject `min_overlap_voxels < 1` in both API and CLI; add a disjoint-components test with `min_overlap_voxels=0` expecting failure.

2. **Major** — [eval/metrics.py:271](../../../eval/metrics.py#L271)
   Lesion detection uses max overlap per GT and per prediction. A single predicted connected component bridging multiple GT lesions can give recall `1.0` and precision `1.0`, even though distinct lesions were merged. Conversely, split predictions can be over-credited. This may match the stated ATLAS convention, but it is dangerous for "distinct lesion" correctness.
   **Fix:** explicitly document this as many-to-many detection, add tests for one-pred-overlaps-many-GT and many-pred-overlap-one-GT, and optionally add a one-to-one matching metric using bipartite assignment.

3. **Major** — [eval/metrics.py:152](../../../eval/metrics.py#L152)
   Surface Dice is voxel-boundary-count weighted, not physical surface-area weighted. With highly anisotropic voxels here, roughly `~1 x ~1 x 6 mm`, this can bias surface Dice and HD95 toward slices/faces with more sampled boundary voxels rather than true surface area.
   **Fix:** implement surfel/area-weighted surface distances, or clearly label this as voxel-boundary surface Dice rather than standard normalized surface Dice.

4. **Major** — [eval/report.py:231](../../../eval/report.py#L231), [benchmark_summary.md:202](benchmark_summary.md)
   Boundary metrics have `n_valid=10`, because the two empty-prediction failures are excluded as NaN, but the headline table reports HD95/ASSD/surface Dice without `n_valid`. That makes boundary performance look better by silently dropping catastrophic misses.
   **Fix:** show `n_valid` in the benchmark summary and add an explicit "2/12 undefined due to empty predictions" note beside boundary metrics.

5. **Major** — [benchmark_summary.md:107](benchmark_summary.md)
   The comparison to published DeepISLES numbers appears wrong or at least uncited/mismatched. The Nature Communications article says DeepISLES over the full test set yielded Dice `0.82 ± 0.12` and lesion-wise F1 `0.86 ± 0.21`, not the summary's "mean Dice ≈ 0.78, lesion F1 ≈ 0.71." This understates the local gap, especially F1.
   **Fix:** cite the exact source table/figure and compare like-for-like: same cohort, same statistic, same lesion-wise F1 definition. Do not claim local median F1 `0.61` is "close" without confidence intervals or metric-definition confirmation.

6. **Major** — [analysis_01_pull_deepisles.sh:47](../../analyses/analysis_01_pull_deepisles.sh#L47), [benchmark_summary.md:188](benchmark_summary.md)
   The container is pulled as `isleschallenge/deepisles:latest`. That is not reproducible; a future rebuild can silently change model weights, code, CUDA stack, or preprocessing. Existing sandbox reuse only checks size.
   **Fix:** pin by immutable digest, record `apptainer inspect`, Docker digest, build date, and DeepISLES git/version metadata in the report.

7. **Major** — [analysis_02_run_deepisles.sh:68](../../analyses/analysis_02_run_deepisles.sh#L68)
   Idempotency skips any existing prediction file without validating it. A truncated file, stale output from a previous image, wrong affine, or empty mask from a failed run will be accepted forever.
   **Fix:** write to a temp path, validate NIfTI readability, shape/affine, non-corruption, and record a manifest. For empty masks, require explicit "valid empty" detection from logs or flag them for manual review.

8. **Major** — [eval/run_eval.py:446](../../../eval/run_eval.py)
   Prediction discovery falls back to the first `*.nii.gz` in a subject directory. That can silently evaluate the wrong file, such as an auxiliary mask, probability map, or intermediate output.
   **Fix:** require exact filenames unless `--allow-glob` is explicitly passed; validate binary-ish mask values and expected affine/shape before evaluation.

9. **Major** — [eval/loader.py:132](../../../eval/loader.py#L132)
   `resample_from_to(..., order=0)` is the right interpolation for label masks, but the function does not enforce that `ref_img` is 3D. `load_mask` squeezes 4D singleton GT, while `resample_to_reference` uses raw `gt_img.shape`; a future singleton-4D GT could make the target shape inconsistent.
   **Fix:** construct a squeezed 3D reference image before resampling, and add tests for 3D prediction to 4D-singleton GT.

10. **Minor** — [eval/metrics.py:133](../../../eval/metrics.py#L133)
    `volume_metrics` has no shape check and can silently compare arrays of different shapes when called directly. `evaluate_case` catches this only because `overlap_metrics` runs first.
    **Fix:** centralize `_validate_same_shape_3d()` and call it in every metric function.

11. **Minor** — [eval/loader.py:127](../../../eval/loader.py#L127), [eval/loader.py:150](../../../eval/loader.py#L150)
    Masks are binarized with `data > 0` without finite-value checks. NaNs become background silently; probabilistic predictions are thresholded at any positive value, not `0.5`.
    **Fix:** reject non-finite values and require either binary labels or an explicit threshold parameter.

12. **Minor** — [analysis_02_run_deepisles.sh:28](../../analyses/analysis_02_run_deepisles.sh#L28)
    Subject list and array bounds are hard-coded. The evaluator discovers subjects dynamically, so inference and evaluation can silently diverge as the dataset changes.
    **Fix:** generate the SLURM array from discovered subject IDs or a checked-in manifest used by both inference and evaluation.

13. **Minor** — [benchmark_summary.md:254](benchmark_summary.md)
    Scanner-model variability language is too strong for `n=2` groups. "Confirms the framework picks up center stratification" is okay technically, but the report risks implying meaningful scanner effects.
    **Fix:** state "descriptive only; not evidence of scanner effect" and avoid rank-style comparisons across `n=2` centers.

14. **Minor** — [eval/qc_viz.py:31](../../../eval/qc_viz.py#L31), [benchmark_summary.md:102](benchmark_summary.md)
    QC overlays show only one GT-heavy slice. For multi-component failures, tiny missed lesions, and merged/split lesions, one slice can hide the actual failure mode.
    **Fix:** generate a small montage: max-GT slice, max-FP slice, max-FN slice, and component-centered slices for missed lesions.

15. **Nit** — [eval/tests/test_metrics.py:141](../../../eval/tests/test_metrics.py#L141)
    Boundary tests assert broad inequalities rather than exact known values or comparison against a reference implementation. This lets surface-distance definition bugs survive.
    **Fix:** add analytic tests for single voxels, anisotropic spacing, diagonal offsets, empty-empty, one-pred-many-GT, and resampling round trips.
